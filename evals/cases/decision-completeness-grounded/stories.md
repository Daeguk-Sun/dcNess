### Story 1 — 요청 제출부터 승인·재제출까지

**GitHub Issue:** 미등록 (사유: eval fixture)

**As a** 구성원과 지정 승인 담당자,
**I want** 비용 요청을 제출·처리하고 결과에 따라 안전하게 후속 행동을 하길,
**So that** 지급 가능 여부와 다음 행동을 같은 기록에서 확인할 수 있다.

**Acceptance criteria:**
- AC-001 [command]: Given 로그인한 구성원과 유효한 금액·용도·PDF 또는 PNG 증빙 1개, When 요청을 제출하면, Then 요청이 `제출됨`으로 생성되고 구성원 본인과 배정된 담당자에게만 보인다.
- AC-002 [command]: Given 배정된 주 담당자 또는 유효 기간 안의 대리자와 제출된 요청, When 담당자가 승인 또는 반려하면, Then 같은 요청이 `승인됨` 또는 `반려됨`으로 전이하고 처리자·시각·반려 이유가 이력에 남는다.
- AC-003 [agent-read]: Given 보존기간 안의 처리된 요청, When 권한 있는 구성원 또는 담당자가 상세를 확인하면, Then 현재 상태·처리자·반려 시 반려 이유와 증빙 열람 동선이 표시되고 증빙 원문을 열 수 있다.
- AC-004 [command]: Given 반려된 요청, When 구성원이 금액·용도·증빙을 수정해 재제출하면, Then 같은 요청 identity가 `제출됨`으로 돌아가고 이전 처리 이력은 변경되지 않는다.
- AC-005 [command]: Given 이미 처리된 같은 명령의 재시도, When 처리 명령을 다시 실행하면, Then 기존 결과를 반환하고 상태 전이와 지급 대기는 하나만 존재한다.
- AC-006 [command]: Given 증빙 저장 실패 또는 처리 저장 일시 실패, When 사용자가 재시도하면, Then 제출 초안 또는 `제출됨` 상태가 보존되고 중복 요청 없이 완료할 수 있다.
- AC-007 [command]: Given 구성원·담당자·대리자 계정, When 다른 소유자·미배정 요청을 조회·처리하거나 유효기간이 만료된 대리자가 배정 요청에 접근하면, Then 접근이 거부되고 증빙 원문과 개인 식별 정보가 로그에 남지 않는다.
- AC-008 [command]: Given 요청·증빙과 주입 가능한 시계, When 증빙 보존기간 전후의 열람·정리를 실행하면, Then 기간 안에는 권한 있는 주체가 증빙을 다시 열람하고 기간 뒤에는 증빙 원문만 삭제되며 요청 이력에는 삭제 상태와 시각이 남는다.
- AC-009 [agent-read]: Given 지원하지 않는 형식 또는 10MB 초과 증빙, When 구성원이 제출하면, Then 제출을 막고 허용 조건과 오류를 표시하며 금액·용도 입력 초안을 보존한다.
