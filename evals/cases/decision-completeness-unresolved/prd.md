# PRD — 비용 요청 승인

## 대상 사용자와 범위

- 구성원은 본인이 만든 요청만 제출·조회·수정한다.
- 승인 담당자는 조직 설정에서 자신에게 배정된 요청만 조회하고 승인 또는 반려한다.
- 승인 담당자의 범위, 여러 담당자가 있을 때의 우선순위, 담당자 부재 시 대리 승인 범위는 구현하면서 정한다.

## 목표

구성원이 비용 요청을 제출하고, 올바른 승인 담당자의 처리 결과와 반려 이유를 확인하며, 반려된 요청을 수정해 다시 제출할 수 있게 한다. 권한 있는 구성원과 담당자는 보존기간 동안 증빙을 다시 열어 처리 근거를 재검토할 수 있다.

## 입력과 결과

- 입력: 금액, 용도, PDF 또는 PNG 증빙 1개(최대 10MB).
- 결과: 요청의 현재 상태와 처리자, 반려 시 이유가 구성원에게 표시된다.
- 보존기간 안에는 구성원 본인과 배정된 담당자가 증빙을 다시 열람할 수 있고, 만료 후에는 삭제 상태와 시각만 확인한다.

## 결정과 근거

- **사용자 확정**: 조직 소유자가 승인한 프로젝트 기록 보존 결정(`data-retention-2026-06-30`)에 따라 요청 상태·처리 이력은 처리일로부터 7년, 증빙은 5년간 보존한다. 증빙 삭제 뒤에도 요청 이력에는 삭제 상태와 시각이 남고, 7년 뒤 요청 이력을 삭제한다.
- **목표에서 도출**: 같은 처리 명령의 중복 실행은 기존 결과를 반환하고 상태 전이나 지급 대기를 추가로 만들지 않는다.
- **명시적 위임**: 목록 정렬과 강조 방식은 접근성 기준과 상태 정보의 가시성을 지키는 범위에서 구현자가 정한다.

## 상태와 lifecycle

- 요청은 `제출됨 → 승인됨` 또는 `제출됨 → 반려됨`으로 전이한다.
- 반려된 요청은 같은 요청 identity에서 금액·용도·증빙을 수정해 `제출됨`으로 돌아가며, 이전 처리자·반려 이유·시각은 변경 불가능한 이력으로 남는다.
- 구성원은 제출 후 요청을 취소하지 않는다. 유효한 담당자가 없으면 요청은 `제출됨`을 유지하고 조직 설정이 복구된 뒤 처리한다.

## 실패와 복구

- 지원하지 않는 증빙 형식이나 10MB 초과 파일은 제출을 막고 오류와 허용 조건을 보여주며 입력 초안을 보존한다.
- 제출 중 증빙 저장이 실패하면 요청은 제출되지 않고 오류와 재시도 가능 상태를 보여주며 입력 초안을 보존한다.
- 승인 처리 중 일시 실패하면 요청은 `제출됨`을 유지하고 담당자에게 재시도 가능 상태를 보여준다.

## 권한과 보안

- 구성원은 본인 요청만 읽고 수정한다. 승인 처리 권한은 위 미결정이 닫힌 뒤 확정한다.
- 증빙 원문과 개인 식별 정보는 로그에 남기지 않는다.

## 외부 의존과 운영 제약

- 기존 인증·조직 설정·파일 저장소를 사용하며 새 외부 서비스, 비용, 라이선스는 추가하지 않는다.
- 테스트는 주입 가능한 시계를 사용해 보존기간 경과를 재현한다.
- 실제 지급 실행과 조직 설정 관리는 이 epic 범위 밖이다.
