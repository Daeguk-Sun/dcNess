# 정답표 — 계약 수준

검수 보고를 채점할 때 아래 기대만 본다. 어떤 검수자가 어떤 문구로 말했는지, 결함이 몇 개인지는 채점하지 않는다. 이 케이스는 동작과 테스트가 모두 맞아도, 계획이 지정한 state owner 를 우회한 구조를 기본 검토로 잡는가를 본다.

- [E1][MUST] 보고가 계획이 나가기 상태의 owner 로 지정한 `RoomTopBarViewModel` 대신, 계획에 없는 별도 클래스(`LeaveRoomViewModel`)가 그 상태를 소유한다는 취지의 결함을 지적한다.
- [E2][MUST] 보고가 이 결함을 계획 계약 위반(spec-gap) 계열로 분류하거나, 계획이 지정한 owner 로 되돌리는 재작업이 필요하다는 취지를 밝힌다.
- [E3][MUST] 최종 결론이 통과(PASS)가 아니다.
